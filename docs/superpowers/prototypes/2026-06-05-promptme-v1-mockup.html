数据怎么流

桌面与手机经 ntfy（无账号 HTTP 推送）共享一条 topic + 带类型消息：capture 上行(→收件箱)、today 下行(今日待办→桌面 Hub)、pomo-* 双向(番茄)。主链路仍是电脑录入→手机执行；记账只落手机。手机端只整理与执行，不重录。

相比 V0 变了什么

砍掉日历订阅 / 飞书导入 / 四象限；新增桌面捕获 + 收件箱 + 3 Tab（收件箱 / 待办 / 复盘）。待办屏按 GTD 智能清单（今日 / 下一步 / 即将到来 / 将来也许）组织，领域色标 + 面包屑 + MAP 诊断标签接替四象限；统计缩到右上角；保留正反馈 + 福格闭环。

AI 在哪出现（吸收参考稿，配色用我们的）

顶部 提示横幅：此刻就做的降门槛一步 + 动机星级 + 换一条；后台 异步分析每条是否合理、是否满足 M/A/P，给逾期 / 偏大项打 需提示 并建议变小；复盘屏做整理 / 复盘。不取参考稿的蓝色。

任务标签 = MAP 诊断（AI 异步打 · 统一右侧）

M 高A 高M 低A 低需提示

颜色按「高 / 低 / 需提示」三档（跨 M/A/P 统一：M 高=A 高、M 低=A 低）：高=绿（动机/能力足够，好）、低=红（不足、需改进——难启动=A 低、动机弱=M 低）、需提示=黄（该触发 P 干预）。是 M / A / P 哪个维度只看文字，由 AI 分析判断写入。标签靠右、压低行高。

字体与气质

沿用 V0：Fraunces（柔衬线）做大字与数字，PingFang SC 做中文正文。米色纸感 + 颗粒，刻意做成「手记 / 教练」而非「待办压迫感」。

这是原型，不是终稿

用于对齐 V1 的视觉与交互手感，定稿后据此写 Flutter 实现计划。颜色、字号、文案、流程都可改——告诉我哪里不对。
