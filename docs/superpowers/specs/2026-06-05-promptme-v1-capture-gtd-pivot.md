# PromptMe v1 设计 —— 桌面捕获 + GTD + 福格对抗(MVP 转向)

> 状态:设计已确认,待写实现计划
> 日期:2026-06-05
> 前作:[v0 设计](2026-06-03-promptme-v0-design.md)(本文是对 v0 的方向性收敛与删减,不是推翻)

## 1. 背景与动机

v0「第一波」做完后,作者自测得出一个关键信号:**Demo 做完,自己都没有每天打开的欲望**。复盘后认定这不是功能不够,而是**价值假设**错位:

- v0 解决的是「我忘了」(提醒);作者的真实痛点是「**想法太多、不知道下一步、记录太麻烦**」(执行 + 收集)。
- 作者是重度知识工作者 / 架构师,真实工作流是「**输入发生在电脑、执行发生在手机**」;而 v0 的输入(飞书 md 粘贴、日历订阅)仍偏「规划优先」,摩擦大。
- 北极星不变:**自己每天真用得上;最少运维**。

**转向**:从「日程提醒工具」收敛为「**把想法变成行动的引擎**」——电脑零摩擦捕获,手机负责整理与执行,AI 在该出现的地方出现。

## 2. 产品定位

> **PromptMe = 把想法变成行动的引擎。**
> 电脑随手捕获 → 手机 Inbox 整理 → 今日执行(福格对抗)→ 正反馈 / 复盘。

链路:

```
电脑敲一句(全局热键)
   → ntfy(HTTP 推送)
   → 手机 Inbox(收件箱)
   → 加入今日
   → 我做到了 / 太难了→无底线降级
   → 连续天数 / AI 复盘
```

主链路是「电脑录入 → 手机整理执行展示」。**唯一的反向回路是番茄钟**:手机把「今日待办」下行同步给桌面,让桌面也能对着具体任务发起专注;但**记账始终落在手机**(见 §5)。桌面因此只有两个职责——**录入**(捕获)与**聚焦**(番茄),永不在桌面管理 / 统计任务。

三套理论的分工:

- **GTD**:Capture(电脑捕获)→ Inbox → Clarify/Organize(加入今日)→ Do(今日执行)→ Review(复盘)。
- **福格 B=MAP**:今日执行屏的对抗闭环——`太难了`降 Ability,`我做到了`+连续天数喂 Motivation,通知/锁屏是 Prompt。
- **AI**:三处协同——①「待办」屏顶部**提示横幅**(此刻该做的降门槛一步 + 动机星级 M + 换一条 = P/M);②**后台异步分析**每条任务是否合理、是否满足 M/A/P,给逾期 / 偏大项打「需提示」并建议变小;③「复盘」屏整理今日 / 复盘未完成。配色统一暖纸感(不取参考稿蓝)。

## 3. 范围

### 3.1 新增
- 桌面捕获:Flutter macOS 托盘 + 全局热键 → 输入框 → POST 到 ntfy;**可选领域标签**(默认 + 自定义,可空)+ **可选目标 收件箱 / 今日待办**(后者直接进待办、可立即番茄)。
- 手机 Inbox(收件箱)+ ntfy 拉取摄入。
- 手机端 3 Tab 信息架构(**收件箱 / 待办 / 复盘**)。
- 「待办」屏:GTD 智能清单(今日待办 / 下一步行动 / 即将到来 / 将来也许)+ **领域色标 + 面包屑(为什么做)+ MAP 诊断标签**;逾期态;快速录入 FAB。
- AI **提示横幅**(待办屏顶) + AI **异步分析**(打「需提示」/ 建议变小)。
- 正反馈:右上角紧凑 chip = 连续天数 + 今日完成 + **总积分**(积分规则实现阶段定)。
- **正反馈做到极致**:每个正向动作都即时**攒分 + 动画**——捕获 +2、番茄完成 +10、任务完成 / 微习惯庆祝;**手机与桌面两端一致**(桌面捕获浮「+2」、桌面番茄完成弹庆祝 + 积分跳动)。奖励最易的行为(捕获),把启动成本→0 的好处当场兑现。
- **番茄钟**:每任务 🍅 预估(AI 估)/ 已完成;专注屏(标准 25 / 5 / 15);完成→加积分、专注时长→喂 A 诊断、放弃→AI 标「需提示」(不计入今日完成 / 连续天数)。**每完成一个 🍅 弹短暂庆祝**(彩纸 + 🍅 印章 + **积分跳动** +10、总分滚动,约 1.5s 自动进短休;沿用「我做到了→庆祝」语言但更轻快)。**桌面端也能发起**——从手机下行同步的「今日待办」里选一条 → 置顶小窗(可调透明度)本地倒计时 → 完成事件上行,**记账落手机**(见 §5 双向契约);**桌面完成同样弹庆祝 + 积分跳动**(与手机同语言),两端正反馈一致。
- 设置页「捕获同步」卡(ntfy server / topic / 立即拉取 / 上次同步时间)。

### 3.2 删除(功能删减)
- **苹果日历订阅**:`CalendarDao`、`CalendarSubscriptionService`、`ics_parser`、`schedule_section`(日程区)、订阅设置卡;`Subscriptions` / `CalendarEvents` 表。
- **飞书导入**:`feishu_importer`、`feishu_markdown_parser`、`feishu_import_sheet`、飞书设置卡及相关测试。
- **四象限 UI**:`quadrant_section`、今日页的象限分组;`Quadrant` 在 UI 层不再出现。

### 3.3 保留
- **统计正反馈**:连续天数 / 今日完成率(`stats_header`)。
- **福格闭环**:`我做到了`(庆祝 + 连续天数)、`太难了`(选原因 P/A/M → 无底线降级 → 2 分钟微习惯)、已完成清单(点重开 / 右滑删除)。
- **AI**:`prioritize`(整理今日)、`review`(复盘未完成)、`downgrade`(降级文案)+ AI 设置卡(OpenAI 兼容,讯飞/DeepSeek/Qwen 预设 + 测试连接)。
- **本地通知**。

## 4. 手机端信息架构(底部 3 Tab)

### Tab ① 收件箱 Inbox
- 列出捕获原样条目:桌面经 ntfy 来的 + 手机 `+` 手记的;**领域标签随捕获带入**(有则显色标 + 标签 chip,无则「未分类」),整理时可再补。
- 手机 `+` 手记 / 桌面捕获时都可**顺手选领域标签**(默认 + 自定义,可不选——保持零摩擦捕获)。
- 每条:点开 →「加入今日 / 删除」。
- 进 App / 下拉 / 回前台 → 从 ntfy 拉新捕获写入。
- **过滤 / 优先今日**:顶部过滤条按**时间**(今日 / 全部,默认今日优先)+ **领域标签**(工作 / 自媒体 / …)筛;列表今日捕获置顶。
- **一键全部加入今日**:批量把当前(过滤后)条目全部置 `scheduledDate=今天` → 进待办,免逐条左滑。
- Tab 上带未读数(Inbox 条数)。
- 排序:今日优先,其余按 id 倒序(新→旧),不引入新列。

### Tab ② 待办 To-do(GTD + 福格 + AI)
- 顶部:**右上角紧凑 chip** = 🔥连续天数 │ ◎今日完成 │ ★总积分(原大卡统计缩小、精简)。
- **AI 提示横幅**(置顶,取代旧「先做这件」聚焦卡):AI 生成的*降门槛*下一步 + 动机星级(M)+「换一条」。
- **GTD 智能清单**(参考 Things / Todoist),今日待办置顶,其余按时间 / 状态:
  - **★ 今日待办**(已排期今天)→ 执行主区;
  - **下一步行动**(无日期)、**即将到来**(有日期,显日期)、**将来也许**(置灰)。
- 每条任务:**领域色标**(接替四象限:工作 / 自媒体 / 学习 / 家庭…)+ **面包屑**(关键结果 › 执行任务 = 为什么做)+ **MAP 诊断标签**(M/A/P 高/低 + 需提示;颜色按 高=绿 / 低=红 / 需提示=黄,跨 M/A/P 统一;由 AI 异步分析判断写入)。
- **卡片布局**:标题 → 面包屑 → **底部一条横向 meta 行**——`🍅 领头(进度/预估)→ MAP 诊断 → 状态 flag(逾期/等待/日期),左对齐单行(挤则换行)`;**不再把异类信息竖排右列**。今日待办卡 meta 行**右端带「▶ 专注」**按钮,直接发起番茄(与桌面 Hub 的「专注」一致);非今日卡(下一步/即将/将来)不带 🍅、不带专注按钮。
- 福格闭环:左滑 `我做到了`(庆祝 + 连续天数 + 积分)· 右滑 `太难了`(**压缩版 ~30% 小 sheet**:一句话标题 + **一行 P/A/M chip**,删冗余安慰文案 → 选原因即打标喂复盘 → 无底线降级 → 微习惯)。**降级在原任务上记降级链 + 次数 + 原因**(微习惯挂原任务,复盘可追溯;见 §6)。
- **逾期态**:被推迟过的项标红「已推迟 N 次」,AI 可打「需提示」并建议变小。
- 下方:已完成清单(点重开 / 右滑删除,分页加载)。
- **FAB**(右下 `＋`):手机随手记一条 → 收件箱。

### Tab ③ 复盘 Review(数据 + AI)
- **顶部日历切换**:`‹ 日期 ›` + 📅,选某天 → 下面数据分析与 AI 复盘都基于这天(默认今天)。
- **数据分析**(新增,纯本地统计):当日 🍅 番茄数 / 任务完成(x/y)/ 完成率 / 专注时长四块瓦片 + **近 7 天番茄数迷你柱图**(今日高亮)。支持日历切换看任意一天。
- **当日 AI 一行结果**(数据下方常驻):自动给一句当日 AI 解读(状态 + 卡点 + 明日最小步),无需点按。
- **AI 复盘入口内联**:放在「数据分析」区头同一行的小链接 `✨ AI 复盘 →`(**不再做大功能按钮**),点开深聊——保持现有 `整理今日`(排序 / 聚焦)、`复盘未完成`(定位 M/A/P),基于当日所有数据。
- AI 仅此屏出现。

> 备选(未采纳):单页「三块」(今日一件事 / 今天做了什么 / AI 复盘)。3 Tab 更贴 GTD 的「收集与执行分离」,故采用。

### AI 的三处角色

1. **提示横幅**(待办屏顶,P+M):AI 给「此刻就做的最小一步」+ 动机星级,「换一条」每日限若干次。
2. **异步分析**(后台,非阻塞、按需触发,不每条都打 AI):对捕获 / 任务判断「目标是否合理、是否满足 M/A/P」,产出打标(如「需提示」)、建议(变小 / 拆解 / 立刻打电话),写回该条供列表展示。
3. **复盘屏**:`整理今日`(排序 + 聚焦)、`复盘未完成`(定位 M/A/P + 修法)。

> **原型**:`docs/superpowers/prototypes/2026-06-05-promptme-v1-mockup.html`(高保真,暖纸感)。视觉 / 交互吸收了参考稿 `promptme_ui_spec_complete.html` 的长处(提示横幅 + MAP 信号 + 卡片状态 + 精简事件行),但**配色保留我们这套暖纸感**,不取其蓝。

## 5. 桌面捕获 + ntfy 管道

桌面有且只有两个职责:**录入**(捕获)、**聚焦**(番茄)。两者都经同一条 ntfy topic,用**带类型的消息**区分。桌面始终是「薄镜像」——不存任务真相、不做统计,一切记账落手机。

### 5.1 桌面(Flutter macOS)
- **统一入口 = 菜单栏 Hub(单一 popover)**。系统托盘常驻(`tray_manager`)+ 全局热键(`hotkey_manager`,默认 `⌥Space`,可改)唤出**同一个面板**,一个面板两件事:
  - **上半 = 捕获**:输入框,**焦点默认在此**——想记直接打字、回车发 `capture` → toast「已捕获 +2 分」;Esc 收起。可顺手选**领域标签**(工作 / 自媒体 / 学习 / 家庭 + 自定义,可不选=未分类)。**可选目标**:`收件箱`(默认,纯收集)/ `今日待办`(直接进待办、马上能专注)——解决「桌面番茄基于待办、但捕获只到收件箱」的断点。
  - **下半 = 今日待办**:手机下行 `today` 快照渲染成列表(领域色点 + 标题 + 🍅),每条一个「专注」按钮;**点即聚焦**。
  - 底部 = 同步状态(ntfy 已连 / 上次同步 / ⚙设置)+ **`↻ 同步` 手动同步按钮**。
  - **托盘图标兼状态**:空闲显图标,番茄运行时显 🍅 + 倒计时,不开面板也看得到。
- **手动同步(`↻ 同步`)**:常驻订阅是 best-effort,睡眠唤醒 / 断网重连 / 刚在手机改完时给个「立刻拉」的逃生口。点一下做三件事:① **flush 出站队列**——重试任何因离线没 POST 出去的 `capture` / `pomo-*`;② **拉入站**——`GET …?poll=1` 取最新保留的 `today` 快照,刷新今日待办 + 「上次同步」时间;③ **重连**订阅流。托盘右键菜单也放一项「立即同步」。**边界**:只能取手机**已发布**的最新快照,无法强拉手机即时生成(手机非常驻订阅,见 §9)。
- **常驻订阅**:桌面是长驻进程,持一条 ntfy 订阅流(SSE / `GET …?poll=0`),**近实时收 `today` 快照**,本地缓存「今日待办」(只读)落到 Hub 下半。
- **聚焦 / 番茄钟小窗**:在 Hub 下半点任务「专注」(缓存为空则在捕获框手输任务名,该名同时作一条 `capture` 上行)→ 发 `pomo-start` → Hub 收起、留下一个 `always-on-top` 置顶小窗(尺寸小仅作提示、**透明度可调** window opacity);倒计时纯本地(按 `startTs + workMin` 算,不依赖实时连接);完成 / 放弃发 `pomo-stop`。
- 配置:ntfy server + topic(与手机共享同一口令)。
- 工程结构:独立的轻量 Flutter desktop 工程 `frontend/promptme-capture/`(避免把 desktop-only 依赖塞进手机 App);与手机端共享的只是 **ntfy 契约**(server / topic / 消息格式)。

### 5.2 手机(摄入 + 下行发布)
- **摄入**:进 App / 下拉 / 回前台 → `GET https://<server>/<topic>/json?poll=1&since=<lastId>` → 按 ntfy 消息 id 去重 → 分派:`capture`(按 `dest` 写 Inbox 或置今天进待办)、`pomo-start/stop` 对账(见下)→ 更新 `lastId`。`dest=today` 摄入后回发一次 `today`。**无持久连接、无 FCM**,纯按需 HTTP 拉取。
- **下行发布 `today`**:在「加入今日 / 设🍅预估 / 完成任务 / 开 App」时,把当前「今日待办」全量快照 `POST` 到同一 topic,供桌面订阅落地。全量幂等(last-write-wins),不做增量。
- **记账(唯一真相源)**:收到 `pomo-stop reason=done` → 🍅+1、加积分、把专注时长喂 A 诊断;`reason=abort` → AI 标「需提示」。账记完后随手重发一次 `today` 快照,桌面对齐。

### 5.3 ntfy 契约(一条 topic + 带类型消息)
单条 topic 承载双向流量,消息体为 JSON,带 `type` 与 `src`(`desktop` / `phone`),每端**忽略自己 `src` 的消息**:

| `type` | 方向 | 发送方 | 载荷 | 接收方动作 |
|---|---|---|---|---|
| `capture` | 上行 | desktop | `{text, dest:inbox\|today, label?, ts}` | 按 `dest` 写 Inbox 或置今天进待办;`label`(领域,可空=未分类)直接落到 `Task.domain`,与待办一致 |
| `today` | **下行** | phone | `{tasks:[{id,title,domain,tomato:{done,est}}], ts}` | 桌面**替换**今日待办缓存 |
| `pomo-start` | 双向 | 发起端 | `{taskId,title,startTs,workMin,round,ts}` | 另一端按 `startTs+workMin` 本地倒计时、起镜像 |
| `pomo-stop` | 双向 | 结束端 | `{taskId,reason:done\|abort,ts}` | 手机据此**记账**;桌面据此收小窗 |

- `since`:上次已摄入的 ntfy 消息 id / 时间,存 prefs(手机用)。
- MVP 不引入加密 / 签名;topic 长随机串当口令即门槛(见 §9)。

## 6. 数据模型(尽量复用,不大改库)

- **捕获条目 = `Task`**:`source = TaskSource.capture`(枚举新增值,追加到末尾)、`title = 捕获文本`、`status = pending`;`dest=inbox`→`scheduledDate = null`(进 Inbox),`dest=today`→`scheduledDate = 今天`(直接进待办)。
- **领域标签 = `Task.domain`**:捕获 / 新建时即可手选(工作 / 自媒体 / 学习 / 家庭 + 自定义,**可空=未分类**),收件箱 / 待办统一显示色标;**MAP 诊断标签仍由 AI 异步打,不在捕获手设**(两类标签分工:领域=用户分类、MAP=AI 诊断)。
- **Inbox 查询**:`scheduledDate IS NULL AND status = pending`,按 id 倒序(新增 `TaskDao.watchInbox()`)。
- **加入今日**:置 `scheduledDate = 今天`(条目即从 Inbox 移出、进入今日;复用现有 `watchTasksForDate`)。
- **四象限列**:`quadrant` 列保留但 UI 不再用,插入时给默认值(`importantUrgent`),避免库迁移;未来需要再以迁移移除。
- **同步游标**:`ntfy_topic`、`ntfy_server`、`ntfy_last_id` 存入 `SettingsController`(SharedPreferences)。
- **待办屏新增字段**(实现阶段细化,MVP 从简):
  - `领域 domain`;`MAP 诊断标签`(AI 异步写回:维度 M/A/P + 高/低 / 需提示）:新增轻量字段;
  - `面包屑 / GTD 上游`(目标 → 关键结果 → 项目):MVP 先存「所属目标 / 项目」文本,完整 6 层树后置;
  - `逾期`:由 `scheduledDate < 今天 && pending` 或 `rolloverCount` 派生,不新增列;
  - `AI 分析结果`(需提示标记 / 建议文案 / 动机星级 M):新增字段,供 AI 异步写回;
  - `总积分 points`:累计计数,**每个正向动作即时加分**(捕获 +2 / 番茄完成 +10 / 任务完成 / 微习惯 / 连续加成…具体数值实现阶段定),手机与桌面两端都触发加分动画;存 prefs 或汇总表。
- **番茄会话记录**(新增轻量表,供复盘「数据分析」按日聚合 + 喂 A 诊断):`{date, taskId, 时长, 结果 done/abort}`。**每日统计**(🍅数 / 完成数 / 完成率 / 专注时长)由「完成事件 + 番茄会话」按 `date` 聚合派生,日历切换即换 `date` 过滤;不引入重型分析表。
- **降级关联(便于复盘)**:降级**不新建独立任务**,而是在原 `Task` 上记 `downgradeLog: [{level, reason: P/A/M, microText, ts}]` + 当前 `downgradeLevel`、`microStep`(当前最小步文案)。微习惯始终**挂在原任务身上**(UI 显「来自原任务 X · 已降级 N 次」),复盘据此追溯:某任务降级几次、卡在 M/A/P 哪环。锁屏微习惯卡完成 / 再降级都写回同一条。

## 9. 已知取舍 / 风险 / 未来

- **ntfy 公共 topic 明文可被猜到** → 用长随机串当口令;敏感内容后续自托管 ntfy 或加鉴权。
- **手机按需拉取(poll-on-open)**:主链路「捕获完晚上开 App 才看到」,无实时推送提醒(够验证;要实时再接 ntfy 推送 / FCM)。番茄钟的 `today` / `pomo-*` 走同一 topic,**桌面常驻订阅近实时**,但手机仍是 poll-on-open——所以桌面发起的番茄事件,手机下次打开才追上(够用,桌面才是当下盯着的屏)。
- **桌面今日待办可能滞后**:桌面缓存只是手机上次发布的快照;`pomo-stop done` 时桌面先乐观 +🍅,手机收到后重发 `today` 对齐(最终一致)。缓存为空则退回手输任务名,不卡死。`↻ 手动同步`能救「睡眠唤醒 / 断网 / 漏收」(重拉最新保留快照 + flush 出站),但救不了「手机改完还没发布」(手机离线 / 改动未触发 `today`)——那要等手机下次联网发布。
- **删除量大**,但都在 git 历史,回退无忧。
- **未来**(本期不做,YAGNI):AI 自动 / 按需澄清(client 已具备)、浏览器插件收集箱、**全量双向同步 / 多设备**(Supabase 升级,超出本期番茄钟这条窄回路)、用机摩擦记录、AI 周复盘、跨端。

## 10. 验证标准(MVP 实验)

这是一次 MVP 实验,成败不看功能数量,看一个问题:

> **作者自己愿不愿意每天打开一次?** 连续自用一段时间后,捕获是否真的更勤、晚上是否真的会去执行。

成立,产品才真正开始;不成立,继续改假设而非加功能。
